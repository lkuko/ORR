# 交易体验技术设计

## 操作与视觉

沿用校园交易台的蓝白界面：主色 `#2854d9`、白色 `#ffffff`、背景 `#f5f7f6`、正文 `#203137`、说明 `#66738a`。使用 PingFang SC / Microsoft YaHei，750rpx 流式布局。状态、下一步和主要按钮形成连续的阅读顺序，内容左对齐。交易详情底部固定操作条，保留安全区和正文留白；主要动作蓝色，取消和管理员处理为次要动作。底部订单入口增加清楚的跑腿/二手分区。

新预约直接 `ACCEPTED`，买家当面验货及线下付款后主动确认完成。既有 `PENDING` 的卖家确认和确认前取消继续兼容。取消协商、争议及管理员裁定不变。

## 本人回收站

复用 `product_orders`，分别存储买卖双方的 `buyerArchived` / `sellerArchived` 及对应的 `ArchivedAt`、`ArchiveExpiresAt`、`RetentionDays`、`ArchiveKey` 字段。未归档的旧文档无需迁移，普通列表使用对应 `buyerArchived != true` / `sellerArchived != true` 查询。期限来自服务端时间，7 / 30 天按整 24 小时计算。

`productOrders.archive` 和 `restore` 都走现有身份、幂等、事务入口。只允许 `COMPLETED` / `CANCELLED`。重复归档不得延长期限。恢复只清除本人的字段。另一方和管理台读取不受影响，不物理删除订单、留言或审计。

`productOrders.mine` 接收 `view=trash`，数据库先过滤本人、归档标记和到期时间，再执行游标分页，避免分页后过滤漏项。回收站按本人归档时间排序。时间条件在每次读时重新计算，不加入游标签名；角色、列表类型和状态仍绑定游标。到期后本人列表、回收站与详情均不再提供该记录，恢复返回明确错误。

## 响应速度

校园圈评论接口返回已保存评论和准确评论数，客户端使用回执更新列表，按 ID 去重，保留请求期间新输入，旧详情响应不得覆盖回执。失败保留输入。内容审核继续执行。

订单详情通过 `productOrders.get(includeMessages=true)` 一次获取订单和首批留言，后续翻页独立读取。客户端将状态请求和留言请求分别版本化，刷新或发送后丢弃旧响应。

## 验证与部署

本地真实路由配合模拟存储测试多角色、并发、期限和权限；小程序页面测试验证交互及竞态。开发者工具执行页面编译、真实账号读写和窄屏布局检查。修改现有测试环境，不创建线上付款，不请求用户逐项手机测试，不将模拟多身份验证描述为真实双手机验收。
