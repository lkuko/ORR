# 产品规则

首轮面向一个校区的 20–50 名同学，以校园跑腿为主、文字论坛为辅。原生微信小程序使用真实微信身份；暂不验证学生身份。报酬由双方线下结算。

## 任务与订单

- 一条任务只允许一个人成功接单；接单在云端事务中完成。
- 公开列表和无关用户只能看到大致区域；具体地点仅对发布者和成功接单者返回。
- 接单者标记完成，发布者确认完成。订单中提供文字留言。
- 接单前，发布者可直接取消；接单后，任一方填写原因申请取消，由另一方同意或拒绝。
- 对方拒绝后形成争议，管理员可裁定取消，或恢复到申请前的状态。
- 连续点击和网络重试应避免重复落库；请求超时后保留草稿与未确认请求编号。

```text
OPEN → ASSIGNED → COMPLETION_PENDING → COMPLETED
  └─ 发布者直接取消 → CANCELLED

ASSIGNED / COMPLETION_PENDING → CANCEL_PENDING
  ├─ 对方同意 → CANCELLED
  └─ 对方拒绝 → CANCEL_DISPUTED
      ├─ 管理员同意取消 → CANCELLED
      └─ 管理员恢复 → 申请前状态
```

封禁发布者时，未接任务下架并取消；在途任务下架并进入争议，由管理员处置。仍有封禁参与者时不得恢复任务。状态变更和留痕必须一并提交。

## 论坛与管理

- 论坛支持文字发帖、浏览和评论。
- 公开内容只有在微信内容安全检查明确通过后才展示；检查异常时保留失败状态，允许重试。
- 用户可举报任务、帖子、评论或用户。
- 举报成功后保留提交回执，提供“查看举报记录”；长期入口为“我的 → 我的举报”。仅展示当前微信用户自己的最近 100 条记录，包括举报对象、原因、状态、处理说明和时间。
- 新举报保存提交时可见的公开内容摘要；评论或帖子下架后仍保留本人的举报记录。旧记录没有摘要时使用类型与缩略编号，不重新公开已下架内容，也不向用户返回其他举报人或管理员的身份字段。
- 管理员使用独立网页登录；可处理举报、下架、封禁、裁定取消争议并查看操作记录。
- 管理员操作必须通过云端角色核对，填写原因并记录审计。

## 当前不包含

多校区、学生认证、微信支付、钱包、抽佣、实时聊天、图片上传、点赞和推荐算法。

首轮列表展示最多 100 条；搜索针对已加载任务。留言和评论最多读取 200 条。后续增加分页时应同步修改界面说明和验收范围。

## 必须保留的界面行为

校园服务站视觉设计、留言发送中的同步锁、失败保留草稿、发送成功直接追加服务端结果、旧请求不覆盖新留言或新分类结果、列表保留已有内容并后台刷新。订单列表展示缩略编号，详情可复制完整编号；取消原因和当前处理提示放在同一区域，订单留言与论坛评论采用统一输入布局。
