# 产品规则

首轮面向一个校区的 20–50 名同学，包含校园跑腿、校园二手与文字论坛。原生微信小程序使用真实微信身份；暂不验证学生身份。跑腿报酬和商品货款由双方线下结算。

## 任务与订单

- 一条任务只允许一个人成功接单；接单在云端事务中完成。
- 公开列表和无关用户只能看到大致区域；具体地点仅对发布者和成功接单者返回。
- 接单者标记完成，发布者确认完成。订单中提供文字留言。
- 接单前，发布者可直接取消；接单后，任一方填写原因申请取消，由另一方同意或拒绝。
- 对方拒绝后形成争议，管理员可裁定取消，或恢复到申请前的状态。
- 连续点击和网络重试应避免重复落库；请求超时后保留草稿与未确认请求编号。

```text
OPEN → ASSIGNED → COMPLETION_PENDING → COMPLETED
  └─ 发布者直接取消 → CANCELLED

ASSIGNED / COMPLETION_PENDING → CANCEL_PENDING
  ├─ 对方同意 → CANCELLED
  └─ 对方拒绝 → CANCEL_DISPUTED
      ├─ 管理员同意取消 → CANCELLED
      └─ 管理员恢复 → 申请前状态
```

封禁发布者时，未接任务下架并取消；在途任务下架并进入争议，由管理员处置。仍有封禁参与者时不得恢复任务。状态变更和留痕必须一并提交。

## 论坛与管理

- 论坛支持文字发帖、浏览和评论。
- 公开内容只有在微信内容安全检查明确通过后才展示；检查异常时保留失败状态，允许重试。
- 用户可举报任务、帖子、评论或用户。
- 举报成功后保留提交回执，提供“查看举报记录”；长期入口为“我的 → 我的举报”。仅展示当前微信用户自己的最近 100 条记录，包括举报对象、原因、状态、处理说明和时间。
- 新举报保存提交时可见的公开内容摘要；评论或帖子下架后仍保留本人的举报记录。旧记录没有摘要时使用类型与缩略编号，不重新公开已下架内容，也不向用户返回其他举报人或管理员的身份字段。
- 管理员使用独立网页登录；可处理举报、下架、封禁、裁定取消争议并查看操作记录。
- 管理员操作必须通过云端角色核对，填写原因并记录审计。

## 校园二手

- 商品支持书籍、数码、生活、运动、服饰、其他六类，服务端搜索标题与描述，默认推荐排序，也可按最新排序。新增列表使用游标分页，默认每页 20 条、最多 40 条。
- 发布需填写标题、描述、成色、价格、公开交易区域和 1–6 张照片；图片先压缩为每张不超过 700KiB 的 JPG/PNG，再经服务端上传私有存储和微信异步检测。文本及全部图片明确通过后才能发布；审核异常或超时不能绕过。
- 每人每天最多上传 60 张图、同时最多 50 件有效发布。正常审核中的图片不可反复送审；异常图片最多三次审核尝试。
- 收藏非本人商品，取消收藏同步减少真实计数；收藏夹中已下架商品只保留“商品已下架”占位和移除操作。
- 推荐按 `72 × log2(1 + 收藏数) - 发布小时数` 排序，属于可解释的热度/时效规则，不是个性化或机器学习推荐。排名会随收藏变化，跨页动态列表按 ID 去重。
- 卖家可下架未预约商品，也可重新上架；被管理员下架的商品不能自行恢复。非卖家不能通过旧链接读取已下架商品详情或申请其图片链接。
- 买家预约后商品锁定，订单直接进入待当面交付；旧版待卖家确认的订单仍可处理。买家当面验货、线下付款后确认交易完成。商品同时只能有一个有效预约。
- 旧版待卖家确认时可按原规则取消；待交付后需对方同意，拒绝进入争议，管理员裁定取消或恢复。取消后正常商品恢复在售；管理下架的商品保持下架。
- 买卖双方可分别把已完成/已取消订单移入个人回收站，选择 7 天或 30 天保留，默认 7 天。到期后不能恢复；只隐藏本人列表，不删除共享订单、留言或管理员凭证。
- 交易留言仅买卖双方可读写，订单结束后停止发送。已有订单保留商品、价格和参与者快照；管理下架不删除交易证据。
- 管理台提供商品搜索、状态/可见性筛选、图片预览、商品下架与交易裁定，并记录审计。

需求与验收条件见 [二手模块需求](../specs/campus-market/requirements.md)。代码实现、真实审核链路和双账号真机结果分别记录，未验证项以实施清单为准。

## 当前不包含

多校区、学生认证、微信支付、钱包、抽佣、物流、实时聊天、点赞和个性化推荐。图片上传目前仅用于二手商品，校园圈仍为文字内容。

原跑腿、论坛首轮列表展示最多 100 条；跑腿搜索针对已加载任务，留言和评论最多读取 200 条。二手商品、收藏、交易订单和交易留言采用独立游标分页，不把旧模块的限制套用到新模块。

## 必须保留的界面行为

校园服务站视觉设计、留言发送中的同步锁、失败保留草稿、发送成功直接追加服务端结果、旧请求不覆盖新留言或新分类结果、列表保留已有内容并后台刷新。交易详情首屏固定展示角色下一步，订单详情一次取得订单与首批留言；论坛评论以保存回执更新计数和评论行，不再重读整帖。订单列表展示缩略编号，详情可复制完整编号；二手订单与跑腿订单在统一订单中心切换；回收站从“我的”独立进入，分类管理二手订单和举报记录。

## 记录整理

- “我的”以同级入口展示二手订单、跑腿订单、我的举报和独立回收站；举报入口使用浅金色强调。
- 已结束二手订单、本人举报记录均可删除并选择 7 天或 30 天保留期。举报可整批移入回收站，未处理举报仍继续由管理员处理。
- 独立回收站分为“二手订单”“举报记录”；二手订单进一步选择“我买到的”“我卖出的”。两类均可恢复、左滑单条清理或全部清理；全部清理范围在确认框中明确，仅影响当前分类和本人记录。
- 清理后不可恢复，不物理删除共享订单、留言、举报内容或管理员证据。到期同样停止本人展示与恢复。
- 举报列表显示最近 100 条；批量删除 / 清理会继续读取更早记录，每批最多 20 条，途中失败显示已完成数量，未完成部分可重试。
