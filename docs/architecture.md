# 云开发架构决定

状态：原跑腿/论坛于 2026-11-12 完成规定的双账号关闭调试验收；2026-11-13 新增二手模块已实现并部署两个函数，真实图片审核与新模块真机验收进度见 acceptance.md。正式环境未绑定。

本工程基于微信原生小程序和微信云开发。产品规则见 `product.md`，目录职责见 `project-structure.md`。

## 选型

1. 原生 JavaScript 小程序共 16 个业务页面，保留原 10 页并增加商品发现、发布、详情、个人商品/收藏、交易订单列表和详情。服务层以 action 调用云函数，不再模拟 REST URL。新二手页面按页面作用域引入固定版本 ColorUI，保留原视觉。
2. campus-api 承载模块化业务；media-callback 独立接收平台图片审核事件，按来源、AppID、事件、版本和 trace 校验。独立回调是信任入口隔离，不是把业务拆成微服务；普通写操作继续在单一数据库事务内完成。
3. 微信文档数据库作为唯一业务数据源。任务为聚合根，状态、事件和幂等记录在同一事务提交。前端不直接读取数据库。
4. Vue 独立网页后台保留。使用 CloudBase 账号密码认证，服务端以可信 uid 查询 admin_users 中的启用 ADMIN 角色；没有客户端自助授予角色的接口。
5. 部署源码保持模块化，发布时打包成本地单文件业务入口，wx-server-sdk 与 @cloudbase/node-sdk 作为锁版本依赖。产物不能依赖函数包外目录。

## 数据与身份

- 微信身份只来自 cloud.getWXContext；AppID 由本地打包配置或云函数环境变量绑定，不接受客户端 userId/openid/role，也不会将请求中的 AppID 作为服务端配置。
- 用户 ID = SHA-256(wechat、AppID、OpenID)。业务 ID 是字符串，避免数字比较和 SQL 自增假设。
- admin_users 文档 ID = SHA-256(admin、CloudBase uid)。用户的微信身份不自动成为网页管理员身份。
- 精确地点、取消原因和留言由云函数验证权限后返回。任务大厅始终只返回大致区域；参与者详情可看精确地点。
- users、admin_users、tasks、task_messages、task_events、posts、comments、reports、admin_action_logs 是业务集合，idempotency 是额外的一致性设施集合。
- 新增 products、favorites、product_orders、product_messages、media_assets、media_checks，共 16 个集合；图片字节在私有云存储，数据库保存引用与审核结果。
- 所有集合客户端直接读写均拒绝。管理台也通过云函数访问，不能凭隐藏按钮保护数据。

## 一致性

- 请求 ID 按身份绑定，摘要包含 action 和规范化载荷。同 ID 同载荷重放已提交响应；同 ID 不同载荷拒绝。
- 小程序把未确认写请求的 ID 保存在本地，按用户/环境/action/载荷摘要隔离；网络超时和重启后可复用。业务载荷本身不写入去重缓存。
- 内容安全检查在事务外执行，只有明确 pass 才进入提交；提交前再次检查用户和业务状态。
- 事务内不做 where 查询、不调用外部服务。交易冲突只重试冲突，业务拒绝不重试。
- 用户维护 activeTaskIds，用于封禁时按 ID 处理在途订单。每次任务写入同步维护索引与用户版本，防止封禁与接单竞争漏单。该结构适用于首轮 20–50 人，需要实测多在途任务时的 10 秒事务上限；规模扩大时改为封禁屏障加分批处置作业，不能直接扩展无限长事务。
- 留言写入同时触碰任务版本，确保与完成/下架并发时有冲突检查。
- 订单：OPEN → ASSIGNED → COMPLETION_PENDING → COMPLETED；取消分支与管理员裁定沿用已确认规则。
- 封禁发布者的 OPEN 任务下架并取消；已接任务下架并转争议，保留恢复前状态。仍有封禁参与者时不得恢复。
- 金额只存整数分；输入按十进制字符串解析，响应输出两位小数字符串。

## 边界与待办

- 原跑腿/论坛列表最多 100 条、留言/评论最多 200 条，跑腿搜索只针对已加载数据。二手模块服务端查询标题+描述，使用转义字面量正则和排序键游标；分页绑定筛选、用户及查询时间上界，动态热度仍可能改变翻页位置，不是数据库快照。
- 昵称在内容中为提交时快照，不按昵称认领旧数据或身份。若需要历史内容同步改名，另以用户 ID 批量展示关联实现。
- 正式环境与测试环境分离；未提供正式环境前 release 构建不通过发布检查。
- 真实账号/内容安全/数据库权限/运行时/管理网页认证必须实测。单元测试和模拟器截图只证明相应本地范围。

## 二手模块的一致性与媒体边界

- 商品预订与订单创建同事务，竞争者提交时重读商品，确保只有一个有效预约；价格采用整数分并保存订单快照。
- 收藏 ID 固定为用户/商品组合的哈希，改变 active 时才增减商品计数，计数与推荐键同事务更新。
- 新预约直接进入 ACCEPTED，保留旧 PENDING 订单的卖家确认兼容分支；买家仍须明确确认线下交易完成。
- 已结束订单按参与者分别保留归档标记与期限，只有当前身份的个人列表会隐藏；管理审计和另一方记录不变。恢复仅撤销当前参与者的标记，过期读取由服务端时间过滤。
- 交易详情合并订单与首批留言读取以减少一次小程序到云函数的往返。校园圈评论继续通过微信内容安全检查，成功后使用回执更新页面，避免整帖重读。
- 推荐键为 `发布时间小时 + 72 × log2(1 + 收藏数)` 加唯一 ID，与减去当前时间的评分排序等价；只需在发布/收藏变化时重算。不是个性化推荐。
- 上传先事务保留资产与当日额度，再在事务外上传和送检，最后提交 trace 与幂等结果。重试复用不可变路径和内容摘要；外部送检不具备与数据库的跨系统原子性，因此以首次存入资产的 trace 为准。
- 回调按 trace 的哈希独立保存，可早于上传事务抵达；重复结果不覆盖首条，拒绝结果不能被后续冲突重放升级为通过。
- 资产须属于发布者、通过审核且未绑定其他商品，才可在商品创建事务中绑定。客户端不能传任意云存储路径让服务端签名；可见商品的合格图片才获取短期 URL。已签出的链接在有效期内仍可能访问，管理下架并不能即时撤销此前发出的所有链接。
- 商品状态推进与交易留言触碰双方用户文档，参与封禁冲突检测。activeProductIds 限制为最多 50 件，用于封禁时处理在售商品；该上限不代表已完成最大规模压力测试。
