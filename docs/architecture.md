# 云开发架构决定

状态：2026-11-12 测试环境已部署，双账号关闭调试真机验收通过；正式环境未绑定。

本工程基于微信原生小程序和微信云开发。产品规则见 `product.md`，目录职责见 `project-structure.md`。

## 选型

1. 原生 JavaScript 小程序保留 10 个业务页面，新增本人举报记录页。服务层以 action 调用云函数，不再模拟 REST URL。
2. 一个模块化业务云函数 campus-api，内部划分身份、权限、输入校验、业务模块、存储适配与内容检查。当前规模采用单部署单元，避免无收益的跨函数分布式事务。
3. 微信文档数据库作为唯一业务数据源。任务为聚合根，状态、事件和幂等记录在同一事务提交。前端不直接读取数据库。
4. Vue 独立网页后台保留。使用 CloudBase 账号密码认证，服务端以可信 uid 查询 admin_users 中的启用 ADMIN 角色；没有客户端自助授予角色的接口。
5. 部署源码保持模块化，发布时打包成本地单文件业务入口，wx-server-sdk 与 @cloudbase/node-sdk 作为锁版本依赖。产物不能依赖函数包外目录。

## 数据与身份

- 微信身份只来自 cloud.getWXContext；绑定 AppID，不接受客户端 userId/openid/role。
- 用户 ID = SHA-256(wechat、AppID、OpenID)。业务 ID 是字符串，避免数字比较和 SQL 自增假设。
- admin_users 文档 ID = SHA-256(admin、CloudBase uid)。用户的微信身份不自动成为网页管理员身份。
- 精确地点、取消原因和留言由云函数验证权限后返回。任务大厅始终只返回大致区域；参与者详情可看精确地点。
- users、admin_users、tasks、task_messages、task_events、posts、comments、reports、admin_action_logs 是业务集合，idempotency 是额外的一致性设施集合。
- 所有集合客户端直接读写均拒绝。管理台也通过云函数访问，不能凭隐藏按钮保护数据。

## 一致性

- 请求 ID 按身份绑定，摘要包含 action 和规范化载荷。同 ID 同载荷重放已提交响应；同 ID 不同载荷拒绝。
- 小程序把未确认写请求的 ID 保存在本地，按用户/环境/action/载荷摘要隔离；网络超时和重启后可复用。业务载荷本身不写入去重缓存。
- 内容安全检查在事务外执行，只有明确 pass 才进入提交；提交前再次检查用户和业务状态。
- 事务内不做 where 查询、不调用外部服务。交易冲突只重试冲突，业务拒绝不重试。
- 用户维护 activeTaskIds，用于封禁时按 ID 处理在途订单。每次任务写入同步维护索引与用户版本，防止封禁与接单竞争漏单。该结构适用于首轮 20–50 人，需要实测多在途任务时的 10 秒事务上限；规模扩大时改为封禁屏障加分批处置作业，不能直接扩展无限长事务。
- 留言写入同时触碰任务版本，确保与完成/下架并发时有冲突检查。
- 订单：OPEN → ASSIGNED → COMPLETION_PENDING → COMPLETED；取消分支与管理员裁定沿用已确认规则。
- 封禁发布者的 OPEN 任务下架并取消；已接任务下架并转争议，保留恢复前状态。仍有封禁参与者时不得恢复。
- 金额只存整数分；输入按十进制字符串解析，响应输出两位小数字符串。

## 边界与待办

- 当前列表仍沿用首轮的最多 100 条、留言/评论最多 200 条，界面搜索只针对已加载数据。滚动分页是后续扩展点，不伪造“全量搜索”。
- 昵称在内容中为提交时快照，不按昵称认领旧数据或身份。若需要历史内容同步改名，另以用户 ID 批量展示关联实现。
- 正式环境与测试环境分离；未提供正式环境前 release 构建不通过发布检查。
- 真实账号/内容安全/数据库权限/运行时/管理网页认证必须实测。单元测试和模拟器截图只证明相应本地范围。
