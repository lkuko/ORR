# 小程序视觉改版

范围：微信小程序的 9 个业务页面、共享组件与原生底部导航；保留现有登录、接口、云端数据和订单状态机。网页管理后台保持本轮已验收的功能。

## 设计方向：校园服务站

面向同校同学，让人在短时间内判断“做什么、在哪里、多少报酬、下一步做什么”。首页借用校园服务窗口的指示牌语言：一块蓝色任务发布区是唯一强视觉焦点，黄色只用于其中的发布入口。其余页面以信息清楚为先。

- 校园蓝 `#2854D9`：主要操作、当前选项。
- 纸白 `#FFFFFF`：阅读和填写区域。
- 雾白 `#F5F7F6`：页面底色。
- 墨灰 `#203137`：标题与正文。
- 石蓝 `#66738A`：时间、说明和辅助信息。
- 路标黄 `#F4D269`：首页发布按钮和个人区的轻强调；不作为正文颜色。

字体使用系统中文无衬线：PingFang SC、Microsoft YaHei、系统字体回退，避免小程序下载字体。标题 44–52rpx，任务标题 30–32rpx，正文 28rpx，辅助文字 24rpx。金额使用系统数字字形和等宽数字特性，不引入装饰字体。内容左对齐，金额右对齐。

## 布局比较与取舍

候选 A：大幅宣传图 + 功能宫格 + 卡片瀑布。问题：挤占任务可见区域，也容易把校园互助做成通用电商首页；放弃。

候选 B：紧凑发布区 + 分类/搜索 + 任务清单。采用：入口清楚，任务优先；社区以连续阅读区呈现，订单以状态与下一步提示呈现，避免所有页面长得一样。

```text
跑腿大厅                   订单
┌────────────────────┐    我发布的 / 我接单的
│ 顺路，帮个忙。       │    全部 / 进行中 / 已结束
│ 取件、带餐、校园代办  │    ┌────────────────────┐
│ [发布任务]          │    │ 状态     任务标题   │
└────────────────────┘    │ 地点     报酬       │
[搜索标题或区域]           │ 下一步提示          │
全部 取快递 带餐 代办       └────────────────────┘
待接任务             数量
┌────────────────────┐    校园圈
│ 分类          金额  │    发起讨论
│ 任务标题            │    作者与时间
│ 说明                │    帖子正文
│ 地点      发布时间  │    评论入口
└────────────────────┘    ── 内容分隔，减少卡片 ──
```

## 实施原则

- 不添加虚构订单量、用户数、评价或认证身份。
- 报酬、隐私范围、线下结算保持明确；地点不超出现有权限展示。
- 主操作触区至少约 44px；重复卡片和表单区域最多使用 16rpx 圆角，首页发布区单独强调；无装饰性渐变或统一阴影。
- 加载、失败、空列表分别呈现，失败有重试，空状态有可执行入口。
- 搜索仅筛选已加载任务，订单筛选不改变后端数据；空状态不显示伪造业务数据。
- 只用短暂的按下反馈，不自动播放动画；小屏、长标题、长昵称和底部安全区纳入视觉检查。
- 先编译 WXML，再检查开发者工具中的实际页面；不为视觉验收发布任务或更改真实订单。

## 完成后检查

开发者工具真机尺寸模拟器的截图存于 `.local/verification/frontend-screens/`，覆盖跑腿大厅、订单、校园圈、我的、任务发布与详情、帖子发布和举报。首页与订单清单、论坛连续阅读、个人页的黄色情境强调、表单安全边距均已检查；原生底部图标也在重新编译后正常显示。

检查时发现任务和帖子详情的失败页原先只有文字提示，已统一为包含说明和重试入口的空状态；同时统一了按钮“接单”用语。首页搜索只匹配当前已加载分类的任务标题与公开区域，避免误解为跨全部历史任务搜索。

已验证：`node scripts/check-miniprogram.cjs`；全部 14 个 WXML 模板通过微信编译器；`npm --prefix server test` 的 21 个单元测试通过，其中包括标题/区域搜索、请求乱序保护、订单状态筛选、角色切换与留言防重。模拟器当前未连通内测 API 隧道，因此截图使用本地临时样例或错误状态；未发布任何任务，也未改动云端数据。受桌面焦点切换影响，本轮未选取更窄的设备型号，长标题和长昵称用例已写入本地检查脚本但未完成截图验证。
