# 小程序视觉改版

范围：微信小程序的 10 个业务页面、共享组件与原生底部导航。当前接入微信云函数与云数据库，界面沿用校园服务站设计。

## 设计方向：校园服务站

面向同校同学，让人在短时间内判断“做什么、在哪里、多少报酬、下一步做什么”。首页借用校园服务窗口的指示牌语言：一块蓝色任务发布区是唯一强视觉焦点，黄色只用于其中的发布入口。其余页面以信息清楚为先。

- 校园蓝 `#2854D9`：主要操作、当前选项。
- 纸白 `#FFFFFF`：阅读和填写区域。
- 雾白 `#F5F7F6`：页面底色。
- 墨灰 `#203137`：标题与正文。
- 石蓝 `#66738A`：时间、说明和辅助信息。
- 路标黄 `#F4D269`：首页发布按钮和个人区的轻强调；不作为正文颜色。

字体使用系统中文无衬线：PingFang SC、Microsoft YaHei、系统字体回退，避免小程序下载字体。标题 44–52rpx，任务标题 30–32rpx，正文 28rpx，辅助文字 24rpx。金额使用系统数字字形和等宽数字特性，不引入装饰字体。内容左对齐，金额右对齐。

## 布局比较与取舍

候选 A：大幅宣传图 + 功能宫格 + 卡片瀑布。问题：挤占任务可见区域，也容易把校园互助做成通用电商首页；放弃。

候选 B：紧凑发布区 + 分类/搜索 + 任务清单。采用：入口清楚，任务优先；社区以连续阅读区呈现，订单以状态与下一步提示呈现，避免所有页面长得一样。

```text
跑腿大厅                   订单
┌────────────────────┐    我发布的 / 我接单的
│ 顺路，帮个忙。       │    全部 / 进行中 / 已结束
│ 取件、带餐、校园代办  │    ┌────────────────────┐
│ [发布任务]          │    │ 状态     任务标题   │
└────────────────────┘    │ 地点     报酬       │
[搜索标题或区域]           │ 下一步提示          │
全部 取快递 带餐 代办       └────────────────────┘
待接任务             数量
┌────────────────────┐    校园圈
│ 分类          金额  │    发起讨论
│ 任务标题            │    作者与时间
│ 说明                │    帖子正文
│ 地点      发布时间  │    评论入口
└────────────────────┘    ── 内容分隔，减少卡片 ──
```

## 实施原则

- 不添加虚构订单量、用户数、评价或认证身份。
- 报酬、隐私范围、线下结算保持明确；地点不超出现有权限展示。
- 主操作触区至少约 44px；重复卡片和表单区域最多使用 16rpx 圆角，首页发布区单独强调；无装饰性渐变或统一阴影。
- 加载、失败、空列表分别呈现，失败有重试，空状态有可执行入口。
- 搜索仅筛选已加载任务，订单筛选不改变后端数据；空状态不显示伪造业务数据。
- 只用短暂的按下反馈，不自动播放动画；小屏、长标题、长昵称和底部安全区纳入视觉检查。
- 先编译 WXML，再检查开发者工具中的实际页面；不为视觉验收发布任务或更改真实订单。

## 2026-11-12 布局修正与举报记录

继续使用上面的六色与系统中文字体。此次重点是任务交接时的信息层级：订单卡左侧显示状态，右侧显示缩略编号；完整编号在详情中可复制。取消原因、等待对象与可执行操作归入同一块提示区；留言输入和发送按钮使用统一的 88rpx 高度。标题、正文左对齐，编号与时间仅作辅助。

```text
订单卡                    取消协商
[待管理员处理]   编号 abc…xyz  取消申请
任务标题                  申请原因
区域                 报酬  原因正文，支持换行
下一步提示                 等待对方 / 管理员处理

订单留言                  我的举报
留言记录                  评论举报       待处理
[写一条订单留言] [发送]     举报内容摘要
                          我的原因 / 提交时间
                          处理结果 / 处理时间
```

审查取舍：移除重复的争议提示；编号使用首尾缩略并保留复制入口；举报以连续记录展示，沿用订单中的状态语言。对照此次截图，不增加新的主题色、装饰卡片或宣传区域。长昵称和连续英文在所有阅读区域可换行，固定操作保留触区，避免原生按钮默认边距造成错位。举报成功后保留明确回执与“查看举报记录”入口，“我的”中提供长期入口。

## 举报记录版本验证

`npm run verify` 的 33 项测试、10 页注册检查和管理网页构建通过。原有搜索、请求乱序、订单角色切换、留言发送锁与失败草稿用例保留在 `tests/unit/miniprogram-ui.test.js`；新增举报归属隔离、旧记录兼容、提交回执及查询乱序回归。

微信模拟器使用 390px 和 320px 两种视口，给订单、任务、论坛和表单注入长文本与 64 位编号后检查全部 10 页，并核对取消面板、订单留言和评论输入的实际截图；没有横向溢出。该样例只修改模拟器页面数据，不写云端。

原重构版本已通过微信工具编译和上传。本轮修改的云函数和索引已部署，模拟器使用真实环境读取历史举报；长文本排版检查使用本地页面数据，不创建虚假云端订单。具体截图、视口和手机验证范围记录在 `docs/acceptance.md`，不把旧版本的真机结果记作本轮新页面已通过。

2026-11-12 用户使用 B 账号扫码新版、关闭调试后确认：评论举报和处理结果可见，底部四个导航图标正常，订单编号已缩短且无溢出。该结果是本轮新增真机证据；模拟器 tabBar 破图仍作为工具显示差异记录。

## 管理台与任务工具栏设计（2026-11-12）

管理台采用“校园服务值班台”：固定模块导航，主要阅读区域呈现待办原文、原因、参与者，操作紧邻对应内容。延续校园蓝 `#2854D9`、纸白 `#FFFFFF`、雾白 `#F5F7F6`、墨灰 `#203137`、石蓝 `#66738A`，绿色 `#34715B` 只表达正常或已处理；警示色用于封禁、下架和争议。中文采用 PingFang SC / Microsoft YaHei，正文 14–15px、主标题 28–32px；不加载外部字体。标题与记录左对齐，时间和工具置于次要位置。

比较：放置大统计卡会稀释当前处理目标，且没有对应统计接口；采用模块说明和实际加载条数。原始类型、时间和 JSON 改为可读标签和字段，编号缩略并允许复制，长内容自然换行。移动端导航改成四个等宽入口，记录操作移至内容下方，用户与审计行改成带字段名称的纵向布局。

```text
校园服务站       举报队列                         刷新列表
举报队列         核对原文与举报原因，再作出处理。
取消争议         待处理 / 已处理 / 不予处理        当前条数
用户管理         评论举报       时间             处理此举报
操作记录         原文、举报原因、举报人           下架并处理
                 缩略编号 + 复制                 不予处理

任务详情工具栏
订单编号 abcdef…123456
[复制编号]                      [举报任务]
```

审查：保留现有蓝白产品语义；移除英文装饰标签、通用统计卡和大段原始编号。工具栏两个按钮采用等宽、同高、共同基线，直接位于编号下方，不再把举报单独置于页面中央。桌面与手机分别截图验证；不为排版测试修改真实业务状态。

实施复核：管理台在 1280px、375px、320px 浏览器中核对，修正了 320px 窄屏含系统滚动条时的 15px 横向溢出；完整编号复制与处理弹窗取消正常。微信模拟器当前为 430px，工具栏两按钮顶边、高度相同，长内容无横向溢出。当前 36 项测试及生产构建通过。这里的手机尺寸检查是浏览器与模拟器结果，本轮未新增双账号手机验收，详见 `docs/acceptance.md`。
